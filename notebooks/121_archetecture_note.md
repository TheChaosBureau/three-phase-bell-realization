## 1. Purpose

The purpose of the reduced architecture is to separate the full measurement chain into clean engineering layers:

\[
\text{state preparation}
\to
\text{linear branch-weight generation}
\to
\text{detector nucleation}
\to
\text{winner latch}
\to
\text{future post-click drain / closure}
\]

The key point is that the linear front-end computes the branch weights, while the detector+latch stack converts those weights into one exclusive outcome. This separation is consistent with the earlier delta-ring analysis: unloaded delta = state, resistive extraction = measurement, and the squared-projection law is exact only at the level of absorbed-energy fractions.

## 2. Front-end contract

### 2.1 What the front-end must provide
The front-end must export normalized branch weights \(w_k\) and a shared absorbed-power envelope \(\Gamma(t)\), so that for each branch \(k\),

\[
P_k(t)=\Gamma(t)\,w_k.
\]

Here:
- \(k\in\{1,2\}\) in the two-branch case
- \(k\in\{++, +-, -+, --\}\) in the shared four-branch case

The weights are generated by the exact linear front-end model, not by the detector.

### 2.2 Single-delta / two-mode interpretation
For the single-delta primitive, the unloaded ring state is the normalized two-mode state

\[
a=
\begin{bmatrix}
a_+\\
a_-
\end{bmatrix},
\qquad
|a_+|^2+|a_-|^2=1,
\]

and ideal orthogonal extraction gives

\[
E_i=W_0|u_i^\dagger a|^2.
\]

Thus the front-end computes exact branch energy fractions, but not yet discrete click probabilities. 

### 2.3 Four-branch shared-state interpretation
In the reduced shared-state model, the front-end provides branch weights

\[
w_{xy}(a,b)=|c_{xy}(a,b)|^2,
\qquad
\sum_{x,y}w_{xy}(a,b)=1.
\]

These are the target joint branch intensities before detector nonlinearities.
