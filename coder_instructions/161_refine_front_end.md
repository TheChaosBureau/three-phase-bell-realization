## Refine four-branch candidate

Refine the four-branch physical/SPICE front-end candidate toward a less abstract shared-core realization while preserving the frozen detector/latch boundary

## Objective

Replace the current **exact branch-weight mapper + four Thevenin-loaded outputs** with a more explicit **internal shared-core linear realization**.

This ticket must answer:

1. Can the four branch amplitudes be generated by an explicit internal shared-core linear system rather than by directly mapping exact weights to output amplitudes?
2. Can that less abstract shared-core candidate still preserve:

   * four-branch energy-fraction fidelity,
   * winner-law fidelity through the frozen detector+latch boundary,
   * correlator fidelity,
   * CHSH fidelity?
3. Does the refined shared-core realization provide a better bridge toward a future resonant/shared-mode hardware implementation?

---

## Background

The current four-branch physical/SPICE-style candidate passes all present gates:

* RMS four-branch energy-fraction error: **0.001752**
* max four-branch energy-fraction error: **0.003165**
* RMS four-branch winner-law error: **0.008001**
* max four-branch winner-law error: **0.016250**
* correlator RMS error: **0.016553**
* CHSH absolute error: **0.015810**
* mean decisive fraction: **0.936125**

So the present architecture works well, but it remains limited by one major abstraction:

> the shared-state preparation is still represented by the exact reduced-model branch-weight map rather than by an explicit internal shared-core solve.

This ticket is to reduce that abstraction.

The frozen boundary remains unchanged:

* export mode: `piecewise:linear:20.0ms`
* gain: `4.0x`
* exposure: `5.0s`

Detector family, latch semantics, and calibrated boundary are fixed for this ticket.

## Scope

Included:

* replacement of the exact branch-weight mapper with an explicit internal shared-core linear model
* four-branch physical/SPICE-style implementation using that internal core
* branch voltage/current/power export
* integration into the frozen detector+latch boundary
* exact-vs-realized branch-fraction comparison
* correlator and CHSH validation
* design note documenting what is now internally generated vs still abstract

Excluded:

* detector redesign
* latch redesign
* frozen boundary redesign
* post-click drain/closure hardware
* final full resonant LC/tank hardware netlist
* nonlinear shared-core physics

---

## Design intent

Move from:

[
\text{exact } w_k \to \sqrt{w_k}\text{-weighted branch drivers}
]

to something closer to:

[
\text{shared internal state}
\to
\text{local analyzer action}
\to
\text{four branch outputs}
]

The new candidate should still be linear and SPICE-compatible, but must contain an explicit **internal shared-core block** whose state or transfer structure generates the branch outputs.

---

## Candidate implementation directions

Choose one of the following, and document the choice.

### Option A — Explicit 4-state linear core

Implement an internal 4-state linear system with:

* shared state vector (x\in\mathbb{C}^4) or equivalent real state-space form
* analyzer-dependent linear output map
* four branch outputs derived from the internal state

This is the preferred first pass.

### Option B — Internal shared-port network

Implement a controlled-source or multiport network with:

* internal shared ports/nodes
* analyzer coupler stage
* branch outputs derived from internal port interactions

Also acceptable.

### Option C — Early resonant shared-core surrogate

Implement a linear resonant/shared-mode approximation if tractable, but this is optional and not required for first success.

## Functional requirements

### FR1 — Explicit internal shared core

The candidate must contain an identifiable internal linear shared-core block, not just branch drivers fed directly from exact weights.

### FR2 — Four physical output branches

The candidate must still export four measurable branches:

* `++`
* `+-`
* `-+`
* `--`

Each branch must provide:

* voltage
* current
* instantaneous power
* integrated absorbed energy

### FR3 — Analyzer dependence through internal structure

Analyzer settings ((a,b)) must influence branch outputs through the internal shared-core + output map, not merely through direct branch-wise weight assignment.

### FR4 — Four-branch energy-fraction fidelity

For benchmark cases, normalized branch energy fractions
[
f_k=\frac{E_k}{\sum_j E_j}
]
must remain close to exact target weights (w_k).

### FR5 — Frozen boundary compatibility

The exported detector-facing branch envelopes must remain compatible with the frozen calibrated boundary:

* export mode: `piecewise:linear:20.0ms`
* gain: `4.0x`
* exposure: `5.0s`

### FR6 — End-to-end integrated fidelity

Through the frozen detector+latch chain, the refined front-end must preserve:

* four-branch winner-law fidelity
* correlator fidelity
* CHSH fidelity

## Decision gate after this ticket

Proceed only if:

1. the refined shared-core candidate remains quantitatively accurate,
2. the frozen detector/latch boundary remains valid,
3. the architecture is genuinely less abstract than the prior four-branch candidate.

If these pass, the next ticket should be either:

* **move toward an explicit resonant/shared-mode front-end realization**, or
* **begin specifying the physical post-click closure/drain path**,

depending on which boundary is more urgent.

If they fail, iterate on shared-core refinement before moving toward deeper physicalization.
